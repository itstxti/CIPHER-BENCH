03ASYMMETRIC KEYS
IDLE
Encryption keys — RSA-OAEP encrypts a random AES key to the recipient's public key, then AES-GCM encrypts the actual data. ECDH derives a one-time shared AES key per message via an ephemeral key pair (forward secrecy per message). Signing keys — RSA-PSS / ECDSA prove a message came from the holder of the private key and wasn't altered. A key pair generated for one purpose can't be used for the other — pick before you generate.
Each signature is bound to a timestamp and a random nonce at signing time, so a captured signed package can later be flagged as stale or replayed — the verifier chooses what "stale" means via the freshness window on the Verify tab.
